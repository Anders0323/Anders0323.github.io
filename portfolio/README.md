# 林一川作品集

面向招聘方的响应式新媒体作品集，包含公开作品浏览和单人使用的内容管理后台。当前仓库是可在本地完整运行的原型；默认读取演示数据，尚未连接任何真实 CloudBase 环境，也尚未公开部署。

正式对外发布前必须同时满足：真实内容已迁移到 CloudBase、浏览器端环境变量完整、匿名权限审计通过、预览域名验收通过，并且 `pnpm release:check` 退出码为 0。当前演示数据会被发布门禁主动拦截，这是预期行为。

## 本地运行与质量检查

需要 Node.js 24+ 和 pnpm。进入本目录后执行：

```bash
pnpm install --frozen-lockfile
pnpm dev --host 127.0.0.1
```

常用命令：

```bash
pnpm test       # Vitest 单元/组件测试 + Node 发布门禁测试
pnpm typecheck  # TypeScript 类型检查
pnpm lint       # Oxlint
pnpm build      # 普通本地生产构建；允许演示数据，用于开发验收
pnpm test:e2e   # 本地 Playwright 公开页与后台工作流
pnpm check      # typecheck + test + build
pnpm release:check
```

`test:e2e` 只启动 `mode=e2e` 的本地 Vite 服务，使用确定性的已登录测试身份、内存仓储和本地上传替身；不会请求 CloudBase。这个入口不进入普通开发或生产构建。不要把 E2E 测试身份当作真实账号。

`release:check` 与普通 `build` 不同：它要求 `VITE_CONTENT_BACKEND=cloudbase` 和完整 CloudBase 浏览器配置，并扫描 `dist` 中的演示文案、演示媒体路径及 E2E 标记。现在执行它应当失败；只有完成真实配置和内容迁移后才应通过。

| `03_摄影/01_人车之间` 至 `05_产品与静物` | 对应五个摄影分类；一个子文件夹对应一组摄影系列 |

短视频建议每类 2–3 条。每一条视频在后台按实际封面构图单独选择 `竖版` 或 `横版`，再分别上传匹配的竖版封面、横版封面和 MP4；不要用一个固定方向覆盖所有项目。摄影以“系列”为单位上传，每组 1–30 张，并另存一份每张图片的替代文字。上传限制为：JPG/PNG/WebP 或 PDF 单文件不超过 20 MB；MP4 单文件不超过 500 MB；空文件和同名覆盖都会被拒绝。

## 日常内容管理

CloudBase 和网站托管连接完成后，普通的文字、视频、封面、摄影图片、二维码和简历替换都不需要改代码，也不需要重新部署网站。

1. 打开 `https://你的域名/admin/login`，输入唯一管理员账号和密码。
2. 在“作品管理”新建或编辑短视频、摄影系列、直播项目和 AIGC 作品；在“个人资料”维护个人信息、经历、能力、社交链接和联系方式。
3. 短视频分别上传横版封面、竖版封面和 MP4，再填写标题、分类、角色、年份、简介、说明、数据表现、推荐和排序。
4. 摄影系列和直播现场截图逐张上传，给每张图片填写准确替代文字，用“上移/下移”调整顺序，并明确“设为封面”；AIGC 按最终图片或视频类型录入，视频必须有最终封面。
5. `草稿` 仅后台可见；`已发布` 才在公开页出现；`隐藏` 会从公开页撤下但保留后台数据。
6. 删除操作会显示作品全名，最终确认按钮等待 800 ms 后才可点击；删除不可撤销，应先确认已有备份。
7. 修改个人资料时可独立替换肖像、微信二维码、PDF 简历，并更新邮箱和社交链接。本项目没有手机号字段。

公开个人资料成功加载后，浏览器标签标题会自动使用后台姓名；加载失败或离开公开作品页时保持中性的“新媒体作品集｜内容创作者”。因此替换姓名不需要修改 `index.html` 或重新写代码。

建议先存草稿，预览确认标题、封面裁切、图片顺序和移动端排版，再发布。大文件上传中不要关闭页面；出现安全中文错误时保留原文件并重试。

## 一次性 CloudBase 配置清单

以下步骤需要网站所有者在腾讯云控制台操作；仓库不会自动创建资源、账号或计费项目。实际免费额度和费用以创建环境时控制台显示为准。

按下列顺序执行，避免在规则或角色尚未就绪时录入公开内容：

1. 创建上海地域（`ap-shanghai`）CloudBase 环境，只生成浏览器可用的 Publishable Key；不要把 Secret Key、管理员密钥或其他服务端凭据写进前端环境变量。
2. 启用账号密码认证，关闭公开注册，只创建一个管理员账号并记录其 UID。
3. 创建 `roles/admin` 并先写入该 UID 为 `owner`。可参考 `cloudbase/seed/roles.admin.example.json`，不要提交真实 UID。
4. 创建五个集合：`videos`、`photo_series`、`live_works`、`aigc_works`、`site_profile`。
5. 按集合应用 `cloudbase/rules/videos.json`、`photo_series.json`、`live_works.json`、`aigc_works.json`、`site_profile.json`，再应用 `cloudbase/rules/storage.json`。数据库规则只允许公开读取 `status=published`，存储规则为公开读取、仅 `owner` 写入；复核规则表达式引用的是已完成的 `roles/admin` 种子。
6. 在安全来源中加入本地、预览域名和最终自定义域名；不要使用无限制通配来源。
7. 将下列值写入未跟踪的 `.env.local`；`.gitignore` 已忽略 `*.local`：

```dotenv
VITE_CONTENT_BACKEND=cloudbase
VITE_CLOUDBASE_REGION=ap-shanghai
VITE_CLOUDBASE_ENV_ID=你的环境ID
VITE_CLOUDBASE_PUBLISHABLE_KEY=你的PublishableKey
```

- 完成以上配置后，真实内容可以先通过本地后台写入 CloudBase；这一步不要求网站已经公开托管。确认所有媒体字段保存的是可公开读取的 HTTPS 地址。

先在本机完成管理员验收，再考虑托管：登录 `/admin/login`，录入、编辑、预览和发布四类内容各一条，确认短视频方向选择、摄影/直播截图排序、AIGC 视频封面、草稿/隐藏状态和媒体上传错误提示都符合预期。随后用未登录浏览器做匿名审计：只能读取 `status=published` 的记录；草稿和隐藏记录读取失败；对五个集合的新增、修改、删除全部失败；对受保护存储路径的上传、覆盖和删除全部失败。再登录管理员账号复核授权写入成功。审计不要使用生产内容做破坏性试验，可先使用专门的临时记录并在控制台确认后清理。

## 发布前门禁与交接

在预览构建前，先执行 fixture 审计：确认仓库中的开发演示内容、`fixture-` 媒体文件、`data-origin: fixture` 和 E2E harness 均未进入待发布内容；`pnpm release:check` 会扫描构建产物并在发现这些标记时阻止发布。普通“直播”或“AIGC”真实文案不应因为关键词而被阻止。

所有者在本地管理员验收完成后，使用真实 `.env.local` 执行预览构建和 `pnpm release:check`。将构建产物、门禁输出、五个集合的规则已应用证明、角色种子核对结果和预览验收清单交给负责托管的人员；由该人员在 CloudBase 控制台完成预览托管与域名步骤。仓库没有执行过真实迁移、部署或域名绑定。

## 预览与正式部署

以下是待所有者完成 CloudBase 配置后的操作说明，本仓库没有执行过这些命令：

```bash
pnpm add -D @cloudbase/cli
set -a
source .env.local
set +a
pnpm release:check
pnpm exec tcb login
pnpm exec tcb hosting deploy dist/ -e "$VITE_CLOUDBASE_ENV_ID"
```

第一次部署只使用 CloudBase 默认域名作为预览地址。依次检查首页、全部分类、视频播放、摄影全屏、直播截图浏览、AIGC 图片与视频播放、关于、联系、404 和后台增删改；同时检查 390 px 与 1440 px 宽度没有横向滚动。预览验收后再绑定正式域名。

自定义域名成为公开简历链接前，需要完成域名实名认证、ICP备案（按实际托管和地域要求）、DNS 解析、HTTPS 证书绑定、安全来源更新以及最终移动端/桌面端冒烟检查。没有真实执行的 iOS Safari、Android Chrome、微信内置浏览器或弱网结果不得标记为已通过。

## 导出与季度备份

至少每季度备份一次；大量更新或删除前额外备份一次。

1. 从 CloudBase 控制台分别导出 `videos`、`photo_series`、`live_works`、`aigc_works`、`site_profile` 五个集合，保留 JSON/CSV 原始导出文件和导出日期。
2. 另建 `cloud-media-manifest.csv`，至少包含 `collection`、`record_id`、`field`、`public_url`、`cloud_path`、`backed_up_at` 六列；把视频、封面、摄影图片、肖像、二维码和简历 URL 全部列入。
3. 下载无法从原始素材目录恢复的云端媒体，并与素材母版、集合导出、URL 清单一起保存到两个独立位置。
4. 随机抽查一个短视频、一个摄影系列、一个直播项目、一个 AIGC 作品和个人资料，确认记录能对应到本地文件及 URL 清单。
5. 备份目录建议使用 `YYYY-MM-DD_portfolio-backup` 命名；不要把含真实账号、UID、环境 ID 或密钥的文件提交到 Git。

恢复时先在非生产环境导入五个集合和媒体，核对公开 URL、排序、封面和发布状态，再切换正式环境。内容变更本身不触发代码发布；只有结构、交互、样式、字段或安全规则改变时才需要重新测试和部署代码。
