# 作品集内容扩展设计

日期：2026-08-11  
状态：已获方向确认，待书面复核

## 目标

在现有首页、短视频、摄影、关于和联系页面基础上，扩展直播与 AIGC 两个一级作品栏目，并让短视频案例能够按作品独立选择横版或竖版封面。摄影系列详情改为不规则的编辑式图集，让横图、竖图和特写形成观看节奏。

网站仍以求职作品展示为核心。页面只呈现作品、简短背景和个人贡献，不增加教程、提示词展示、直播完整回放或复杂数据看板。

## 信息架构

公共导航顺序固定为：

1. 首页
2. 短视频
3. 摄影
4. 直播
5. AIGC
6. 关于
7. 联系

新增公共路由：

- `/live`：直播案例列表
- `/live/:slug`：直播案例详情
- `/aigc`：AIGC 作品列表
- `/aigc/:slug`：AIGC 作品详情

首页的主体内容结构暂不扩张，仅同步新增导航与页尾入口，避免首页信息密度过高。直播和 AIGC 作品通过各自一级栏目完整呈现。

## 短视频案例

### 内容规模

人物叙事、品牌表达、现场纪实、社交创意四个分类，每个分类的首期目标为 3–4 个案例。3–4 个是内容准备目标，不作为系统硬上限，后续可以继续新增。

### 封面选择

每个案例新增 `coverOrientation` 字段：

- `portrait`：使用竖版封面，固定显示比例 `3:4`
- `landscape`：使用横版封面，固定显示比例 `4:3`

现有 `verticalCoverUrl` 和 `horizontalCoverUrl` 均保留。列表页根据 `coverOrientation` 选择对应资源和比例，而不是根据浏览器横竖方向改变同一案例的版式。

为兼容既有数据，缺少 `coverOrientation` 的旧记录按 `portrait` 处理。后台保存新记录时必须明确选择一种版式。

### 列表版式

桌面端采用 12 栏编辑式网格：横版案例占较宽栏位，竖版案例占较窄栏位，通过上下错位形成节奏，但仍按 `sortOrder` 保持阅读顺序。移动端按单列顺序呈现，每张封面保留该案例选择的 `3:4` 或 `4:3` 比例，封面下方显示标题、摘要、职责与年份。

图片使用 `object-fit: cover`，只允许裁切，不允许拉伸。封面容器必须显式接管高度，避免 HTML 图片尺寸属性造成异常长图。

## 摄影作品

### 系列列表

摄影一级页面继续展示五个系列入口：人车之间、空间与建筑、活动现场、运动瞬间、产品与静物。系列入口封面保持统一的 `3:4` 比例，保证分类浏览稳定清晰。

### 系列详情

进入系列后展示一组照片，不使用整齐重复的九宫格。布局直接读取每张照片已有的 `width` 和 `height`：

- 横图作为章节性大画面，占较宽栏位。
- 竖图使用较窄栏位，并与前后图片左右错位。
- 接近方形或特写照片作为较小停顿画面，增加留白。
- 连续图片按后台数组顺序展示，视觉错位不能改变键盘与屏幕阅读器的内容顺序。

桌面端使用 12 栏网格和循环的编辑式版型；移动端使用单列，但通过约 `100% / 82% / 68%` 三档宽度、左右对齐和不同段间距建立节奏。照片保持真实宽高比，不强制裁成同一尺寸。

现有全屏查看器继续保留，包括键盘前后切换、Escape 关闭、滚动锁定和焦点恢复。

## 直播栏目

直播栏目只展示截图与简短文字，不上传完整直播回放。

每个直播案例包含：

- 标题
- slug
- 一句话摘要
- 简短说明
- 个人职责（简短文本数组）
- 年份或日期
- 1–12 张现场截图，包含 URL、替代文字、宽度和高度
- 封面截图
- featured、sortOrder、status、updatedAt

列表页使用封面截图、标题和一句话摘要。详情页采用类似摄影系列的编辑式截图流，并在开头展示简短说明和个人职责。截图可进入现有全屏浏览器，不增加视频播放器。

## AIGC 栏目

AIGC 只展示最终作品，不展示提示词、生成过程、模型参数或工具教程。

每个 AIGC 作品包含：

- 标题
- slug
- 媒体类型：`image` 或 `video`
- 最终作品 URL
- 视频作品的封面 URL
- 一句话介绍
- 年份
- featured、sortOrder、status、updatedAt

列表页以作品封面和一句话介绍为主。图片详情直接展示高质量成品；视频详情沿用现有“明确点击后才加载视频”的播放规则。AIGC 页面不展示提示词字段，也不在后台建立提示词输入项。

## 后台管理

后台导航新增“直播”和“AIGC”。

短视频编辑器新增必选的“封面版式”控件，并同时保留横版、竖版封面上传位。发布前校验所选版式对应的封面已经上传。

直播编辑器支持：

- 标题、摘要、说明、职责和日期编辑
- 封面截图上传
- 截图批量上传、替代文字、排序和删除
- 草稿、发布、隐藏状态

AIGC 编辑器支持：

- 图片或视频类型选择
- 最终作品上传
- 视频封面上传
- 标题、简介和年份编辑
- 草稿、发布、隐藏状态

所有媒体仍先解析为 HTTPS 公共地址或 `/media/` 站内地址后才能持久化，不保存 `blob:`、`cloud://`、本地文件路径或原始文件名。

## 数据与仓储边界

新增 `LiveWork` 和 `AigcWork` 领域类型、Zod 公共/后台草稿 schema，以及对应的公共读取和管理员 CRUD 仓储方法。

CloudBase 新增集合：

- `live_works`
- `aigc_works`

公共查询必须固定过滤 `status: published` 并按 `sortOrder asc` 排序。管理员查询可以读取 draft、published 和 hidden。安全规则沿用现有原则：公共只读已发布内容，管理员身份才允许写入。

Memory repository 与 CloudBase repository 必须实现相同接口，以保证本地测试、E2E harness 和线上后台行为一致。

## 加载、空状态与错误处理

直播和 AIGC 列表与详情页沿用现有公共页面模式：

- 加载中显示可访问的状态文本。
- 空列表明确提示“暂时没有已发布作品”。
- 未找到或未发布的 slug 返回安全的 not-found 页面。
- 仓储错误只显示通用重试信息，不泄露 SDK、集合名、查询或凭据细节。
- 媒体加载失败显示现有图片降级状态；视频失败回到封面并允许重试。

## 响应式与可访问性

- 所有列表保持 DOM 阅读顺序，不使用会改变语义顺序的 CSS 排列。
- 封面和截图必须有可编辑替代文字。
- 卡片点击区域、筛选和后台控件满足至少 44px 的触控目标。
- 横竖封面只改变视觉占位，不影响标题和链接的可访问名称。
- 不规则摄影排版在窄屏下退化为稳定单列，避免横向滚动。
- 新增导航在移动端继续使用现有菜单交互与 `aria-expanded` 状态。

## 测试与验收

实现必须遵循测试先行，并覆盖：

1. 旧短视频记录默认使用竖版，新记录按 `coverOrientation` 选择正确 URL 和比例。
2. 四个短视频分类各自能够展示多条横竖混合案例。
3. 摄影详情根据原始尺寸获得横图、竖图和特写版式，同时保持 DOM 顺序与全屏浏览功能。
4. 直播公共列表、详情、空状态、错误与管理员截图排序流程。
5. AIGC 图片与视频作品的公共展示、后台保存以及视频点击后加载规则。
6. Memory 与 CloudBase 仓储契约、published 过滤、排序和安全错误映射。
7. 390 × 844 与桌面视口的浏览器视觉检查，确认无异常长图、拉伸、横向溢出或重复九宫格观感。
8. 完整 typecheck、Vitest、Node release gate、production build、lint 和 diff-check。

## 不在本轮范围

- 直播推流、直播间嵌入或完整回放托管
- AIGC 提示词、工作流、模型参数或生成过程展示
- 访客评论、点赞、收藏或账号系统
- 首页大规模重排
- 云端正式部署或真实内容迁移
