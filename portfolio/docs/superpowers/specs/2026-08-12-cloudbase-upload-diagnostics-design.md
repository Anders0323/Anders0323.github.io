# CloudBase 上传安全诊断设计

## 目标

定位真实 CloudBase 素材上传失败发生在“上传对象”还是“生成公开地址”阶段，同时避免泄露 Publishable Key、登录密码、Token、请求头和文件内容。

## 范围

- 只修改 CloudBase 媒体存储适配层及其单元测试。
- 只在 Vite 开发环境输出诊断信息；生产构建保持静默。
- 页面继续显示现有通用提示，不改变用户可见错误文案。
- 不自动重试，不保存或发布作品，不改数据库与云端权限。

## 诊断格式

开发环境通过可注入的诊断端口记录一个结构化对象：

- `stage`: `upload` 或 `public-url`
- `code`: 从 CloudBase 错误中提取的短错误码；不存在时使用 `UNKNOWN`
- `message`: 固定的安全摘要，不透传第三方原始错误全文

严禁记录文件对象、文件路径、环境变量、认证信息、请求参数或完整第三方响应。

## 流程

1. `storage.upload()` 抛错或返回 `error` 时，记录 `upload` 阶段后抛出现有 `MEDIA_UPLOAD_ERROR`。
2. 上传返回合法结果后，若 `getPublicUrl()` 抛错或返回非法结构，记录 `public-url` 阶段后抛出同一通用错误。
3. 成功时不记录任何诊断。
4. 单元测试分别覆盖两个失败阶段、敏感字段不外泄、生产环境静默和成功路径静默。

## 验证

完成 RED→GREEN 后运行媒体存储聚焦测试、类型检查与 lint。随后仅用已授权的 5.9KB 开发测试图执行一次真实上传，根据安全诊断决定下一步；不触碰正在填写的作品表单。

## 已定位根因与修复

真实诊断确认上传成功、公开地址解析失败。`storage.from()` 返回的兼容存储客户端在没有显式 bucket ID 时，无法用相对 `path`/`fullPath` 构造文件 ID；真实 SDK 上传结果的 `id` 才是完整 `cloud://` 文件 ID。最小修复是调用 `getPublicUrl(uploaded.id)`，不新增 bucket 配置，也不手工拼接 URL。
